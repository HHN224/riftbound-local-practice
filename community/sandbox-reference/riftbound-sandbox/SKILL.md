# Riftbound Sandbox 场景生成

将玩家描述转换成完整的 Sandbox JSON，由玩家导入游戏并实际操作验证。
普通聊天也可使用：读取本资料包后直接接受玩家的局面描述，无需安装工具或连接服务。

## 生成局面

1. 读取 [格式说明](references/format.md)，以 [基础模板](assets/template.json) 为起点。
2. 在 [卡名与 ID 对照表](references/cards.tsv) 查找玩家指定的卡，原样使用 `templateId`。表中只有名称、副标题和 ID，不包含卡牌能力。不要根据文件名、记忆或卡面编号格式猜 ID。
3. 同名卡先按副标题或玩家提供的编号区分；无法确定具体卡或查无此卡时，向玩家确认。不要擅自替换卡牌。
4. 按描述填写双方区域、战场、符文和状态。玩家未指定时沿用模板的手动模式、补牌数量和空白战场；不同实例使用不同 `ref`。示例见 [交战前局面](assets/before-combat.json)。
5. 返回完整、无注释的 JSON。能创建文件时交付 `场景名.riftbound-sandbox.json`；只能聊天时用一个 JSON 代码块，提醒玩家只复制块内 JSON。不要用省略号或仅返回修改片段。

## 能力边界

- 只配置已有卡牌的初始局面；卡牌能力和规则执行由游戏引擎负责，不在 JSON 中添加 `abilities`、费用、战力或自定义效果。
- 只能从空闲行动阶段开始。战斗、法术对决或结算链中途的需求，转换为可操作的前置局面，在 JSON 外简短说明进入后需要执行的操作。
- 预置卡牌不会触发“打出／进场”，也不会模拟此前的对局历史。需要这些过程时，应把牌放入手牌，让玩家进入后操作。
- 不支持的字段不会自动获得含义；不能通过额外字段伪造已贴附装备、临时效果、焦点、待选目标或胜负。
- 对照表不能用于推断卡牌机制。缺少必要机制信息时请玩家补充，不宣称已验证规则或结果。

## 根据反馈修正

玩家会带回导入错误、原 JSON 或实际操作结果。依据字段路径和错误原因修正，保留无关设置，再返回完整 JSON。
网络连接、超时、请求频率或草稿容量错误应先按提示重试或整理草稿，不因此改动局面。
导入成功只表示可加载，是否复现玩家的问题由玩家在 Sandbox 中验证。
