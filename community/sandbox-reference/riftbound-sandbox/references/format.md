# Sandbox JSON v1

以 `assets/template.json` 为完整结构起点。所有键名区分大小写，空区域仍保留数组。
场景 JSON 只有这里列出的配置字段，不包含卡面能力或引擎运行时快照。

## 顶层字段

| 字段 | 填写方式 |
| --- | --- |
| `schemaVersion` | 固定 `1` |
| `id` | 非空场景标识，最长 120 字符；可使用简短英文场景名。同 ID 再次导入会作为新草稿保存 |
| `name` | 玩家可读的场景名称，最长 80 字符 |
| `createdAt` / `updatedAt` | 毫秒时间戳，非负安全整数；不知道当前时间时可用 `0`，导入会更新修改时间 |
| `seed` | 非空随机种子字符串，最长 128 字符；相同配置与种子用于复现 |
| `turnNumber` | 1–999 的整数 |
| `currentPlayer` | `"p1"` 或 `"p2"`，表示谁正在行动 |
| `players` | 必须同时有 `p1`、`p2`，结构见下文 |
| `battlefields` | 战场数组，最多 8 个；通常保留模板的两个空白战场 |
| `runtime` | `{ "opponentMode": "manual" }`；玩家明确需要自动对手时可用 `"ai"` |

`p1` / `p2` 是场景座位，不随玩家在游戏中切换视角改变。手动模式下可切换视角操作双方。

## 玩家配置

| 字段 | 含义 |
| --- | --- |
| `score` / `experience` | 分数／经验，0–999 的整数 |
| `legend` | 一张传奇卡条目，或 `null` |
| `hero` | 一张英雄单位卡条目，或 `null`；英雄槽不属于场上单位区域 |
| `hand` | 手牌，普通卡条目数组 |
| `mainDeck` | 主牌堆，普通卡条目数组，索引 0 是牌顶 |
| `deckFillerCount` | 自动追加到显式主牌堆底部的占位牌数量，0–39；默认 30，自动对手会忽略这些占位牌 |
| `graveyard` / `exile` | 废牌堆／放逐区，普通卡条目数组 |
| `baseUnits` | 基地单位，普通卡条目数组，只能放单位 |
| `baseEquipment` | 基地装备，普通卡条目数组，只能放装备；不表达贴附关系 |
| `runes` | 场上符文数组，格式见下文 |
| `runeDeck` | 可选的符文牌堆数组，索引 0 是牌顶；省略或 `[]` 表示没有额外符文 |

普通卡牌数组每个最多 200 项。`runes`、`runeDeck` 各最多 30 项。
指示物只允许放入对应的单位、装备或战场卡位，不放入手牌、牌堆、废牌、放逐或待命区。

## 卡牌条目

```json
{ "ref": "p1-hand-1", "templateId": "从对照表原样复制的ID" }
```

- `ref`：文档内唯一的非空实例标识，最长 120 字符。两张相同卡也必须使用不同 `ref`，且不能与战场或符文的 `ref` 重复。
- `templateId`：卡名对照表中的精确 ID，最长 120 字符，保留 `·`、`/`、`*` 等字符。
- `tapped`：可选布尔值；`true` 横置，`false` 活跃。需要指定时显式填写。
- `damage`：可选 0–999 整数，表示已有伤害，不表示生命值或战力。
- `damageBy`：可选的伤害来源玩家数组，如 `["p2"]`；最多两项，仅用于 `damage > 0` 的在场单位。
- `faceDown`：可选布尔值。待命区由引擎自动设为背面朝上。
- `boon`：可选布尔值，预置增益，仅用于在场单位。
- `copyFromRef`：可选字符串，仅指示物单位可用；引用同一场景中另一名未预置复制状态的在场单位，不能引用自身或形成复制链。

省略不需要的可选字段，不给非在场单位填 `boon`、`damageBy` 或 `copyFromRef`。
玩家区域的条目归该玩家所有，无需 `owner`；战场单位和待命牌必须额外提供 `owner: "p1" | "p2"`。

## 符文

场上符文：

```json
{ "ref": "p1-rune-1", "color": "red", "tapped": false, "flipped": false }
```

符文牌堆条目：

```json
{ "ref": "p1-rune-deck-1", "color": "red" }
```

颜色只接受 `red`、`blue`、`green`、`yellow`、`orange`、`purple`。符文使用 `color`，不使用 `templateId`。
`tapped` 表示横置，`flipped` 表示翻面；需要可用符文时均填 `false`。

## 战场

```json
{
  "ref": "battlefield-1",
  "templateId": null,
  "controller": null,
  "units": [],
  "standby": []
}
```

- `templateId: null` 是空白战场；使用真实战场卡时填对照表中的 ID。
- `controller` 是 `"p1"`、`"p2"` 或 `null`，不代表战场上每张卡的归属。
- `units` 为带 `owner` 的单位条目数组，可以同时放双方单位；不会因此自动进入战斗。
- `standby` 为带 `owner` 和 `mature` 的卡牌条目数组，只允许具有待命能力的卡；`mature: true` 表示此前回合已放入，`false` 表示本回合放入。
- `units`、`standby` 各最多 200 项。

## 导入与修正

文件大小最多 512 KiB。文档内卡牌与符文合计最多 400 张（含传奇、英雄、战场卡及符文牌堆，不含隐式补牌）。
不要添加 `phase`、`combat`、`abilities`、`power`、附加费用或自定义状态字段；当前解码只保留已支持的字段。
空闲 Action 是固定起点，预置状态不触发打出／进场事件，也不能重建本回合已发生的操作历史。

导入先做结构校验，再由引擎检查真实模板、区域和初始状态。报错中的 `$.players.p1.hand[0]` 表示 p1 手牌数组第一项。
修正失败字段后返回完整文档；不要改变无关卡牌、种子或双方设置。资料可能与玩家安装的版本不同，出现未知模板时先核对游戏版本和资料版本，不编造替代 ID。
